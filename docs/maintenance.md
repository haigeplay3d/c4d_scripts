# 维护与接手

1. 先查看 Git 状态、脚本总表和质量清单；不要把已有未提交修改当作本轮产物。
2. 当前源码位于 C4D 额外脚本路径下，修改 `.py` 可能影响下一次执行。先保存基线，再做小批改动。
3. 保留一脚本一目录；共享库只在确有重复逻辑和明确部署方案时引入。
4. 文档使用 UTF-8。用户说明采用中文，保留英文 UI / 文件名便于查找。
5. 不批量改名、恢复已删图标或清理编辑器文件；先确认用途和 Git 差异。
6. `c4dpref.py` 是保留原位的历史草稿；不要把它作为设置工具运行。
7. 代码变更与整理文档分开审阅；验证后选择明确文件提交，避免 `git add .` 混入未知删除。
8. `.vs`、`.vscode` 当前已被忽略。暂不改宽泛忽略规则；未来若新增 `.github` 工作流，需显式调整规则并验证跟踪状态。
9. 本阶段整理为一次本地 Git 提交；没有选择新许可证、推送远端或发布。发布前核对来源许可、配套资源和验证结果。

## 恢复原则

本次整理前保存了源码工作文件压缩包、完整 Git 历史 bundle、已跟踪改动补丁、暂存补丁及两份 Obsidian 原文。具体本机路径见私人 Obsidian 维护日志。

不要把压缩包直接覆盖到正在使用的脚本目录。先在独立临时目录解压比对，仅恢复需要的文件；完整 Git 历史与工作文件是两种不同基线。新建文档的回退应根据本轮文件清单处理，不删除原有内容。
